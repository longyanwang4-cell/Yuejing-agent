# 阅境 Agent

面向大学生的人际沟通练习工具。带着真实的困扰进来，先判断卡在哪，再看一个史书里的典故，然后由 AI 扮演对方陪你多轮练习，最后按你说过的原话给出评分和下一步建议。3D 书房只用来做成长可视化。

```
说困扰 → 诊断归类 → 看典故 → 命名这个做法 → AI 扮演对方多轮陪练 → 证据化评分 → 决定下一步练什么
```

## 现在是什么状态

- 3D 书房、六篇史书典故（每篇五幕）、六间练习房间都已完成，在 `app/`。
- 后端在 `backend/`（FastAPI）：诊断、陪练、评分三次模型调用，状态机、结束条件、评分数值和下一步决策由后端计算，模型只提议。
- 书架点亮和成长记录读的是浏览器里的真实练习记录，保存在本机，不上传，不需要账号。
- 不配模型 key 也能完整走通，此时界面会标注"离线演示模式（规则驱动，不是模型生成）"。

**还没有验证的**：在线模型路径只用模拟模型测过，没有用真实模型跑过；手机端和多人同时访问也没有测过。详见 [RUN.md](RUN.md) 的"已知限制"。

## 运行

```powershell
cd app && npm install && npm run build
cd ../backend && pip install -r requirements.txt
python -m uvicorn app.main:app --port 8765     # 打开 http://127.0.0.1:8765
```

接入在线模型、部署注意事项、现场兜底方案见 [RUN.md](RUN.md)。

## 目录

| 路径 | 内容 |
|---|---|
| `app/` | Three.js + Vite 前端：书房、历史典故、实景练习三个独立场景 |
| `backend/` | FastAPI 后端、规则引擎、离线兜底、测试 |
| `knowledge/cards.json` | 6 张知识卡，唯一事实源 |
| `prompts/` | 诊断 / 角色模拟 / 评分 三个模块的 Prompt 与 JSON Schema |
| `scenarios/roleplay.scenarios.json` | 6 个练习场景与状态机规则 |
| `tools/validate_all.py` | 改完配置后跑它，检查跨文件一致性 |
| `RUN.md` | 运行、部署、已知限制 |
| `HANDOFF.md` | 早期交接文档，部分内容已过时（见下） |

## 测试


## 边界

- 这是人际沟通练习工具，不是心理咨询或医疗产品，不做诊断，不宣称用户"已经掌握"某种能力。
- 出现自伤等高危表达时，不分类、不练习、不打分，直接给出求助热线。热线号码上线前请对照官方来源再核对一次。
- 知识卡的内容来自公有领域古籍（《左传》《史记》《汉书》《晋书》《晏子春秋》《战国策》），现代解读为自行撰写。
- 没有登录，公网部署时靠调用次数上限保护模型额度，见 [RUN.md](RUN.md)。

## 关于 HANDOFF.md

它写于项目早期，当时的内容载体是一本在版图书。后来改为只用公有领域史书，所以文中凡是讲"原书第几夜""页码指路"的段落都已作废，其余的架构、状态机和异常兜底规则仍然适用。
